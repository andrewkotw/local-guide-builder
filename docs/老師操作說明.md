# 老師操作說明：收取並發布全班網站

這份流程不會把學生資料送到其他服務。您會先在自己的電腦整理網站，再把完整班級網站發布到 GitHub Pages。

## 一、請學生繳交什麼

請每組在網站產生器最後一步按「下載交給老師的網站壓縮檔」，繳交下載到的 ZIP。正常檔名會是：

```text
類型-英文景點名稱-小組名稱.zip
```

例如：`景點-Sea-Breeze-Trail-海風觀察隊.zip`。

不要收 `.localguide` 當成正式網站。那是學生下次繼續編輯用的作品備份，不能直接發布。

## 二、第一次準備

1. 在這個專案資料夾執行 `npm install`。同一台電腦通常只需執行一次。
2. 在方便的位置建立一個班級網站資料夾，例如 `D:\class-sites`。
3. 在班級網站資料夾內建立 `groups` 資料夾，結果應像這樣：

```text
D:\class-sites\
└─ groups\
```

## 三、解壓縮各組 ZIP

每組網站都要解壓縮到 `groups` 裡自己的資料夾。資料夾名稱只要不重複即可，建議加上座號或組號：

```text
D:\class-sites\
└─ groups\
   ├─ 01-sea-breeze-trail\
   │  ├─ index.html
   │  ├─ site-info.json
   │  ├─ style.css
   │  └─ images\
   ├─ 02-happy-market\
   └─ 03-morning-temple\
```

請特別檢查不要多包一層。正確情況是打開小組資料夾後立刻看到 `index.html` 和 `site-info.json`，而不是又看到另一個同名資料夾。

## 四、產生班級首頁

在本專案根目錄執行：

```powershell
npm run build:class-index -- "D:\class-sites"
```

完成後，班級資料夾會多出：

- `index.html`：班級首頁
- `class-style.css`：班級首頁樣式
- `class-index-report.json`：本次加入與跳過哪些組的檢查紀錄

工具會按「景點、美食、廟宇、歷史文化、其他」分類。如果某一組資料有問題，終端機會顯示資料夾名稱與修正方式；其他正確小組仍會正常加入首頁。

## 五、預覽與檢查

在本專案根目錄執行：

```powershell
npm exec vite -- "D:\class-sites" --host 127.0.0.1
```

開啟終端機顯示的網址，逐一檢查：

1. 班級首頁的組數是否正確。
2. 每張卡片的封面與文字是否正確。
3. 每張卡片能否進入該組網站。
4. 該組網站的照片與影片能否顯示。

檢查完按 `Ctrl+C` 停止預覽。

專案也附有三組可直接查看的範例：

```powershell
npm run build:class-index -- "examples/class-sites"
npm exec vite -- "examples/class-sites" --host 127.0.0.1
```

## 六、發布到 GitHub Pages

建議為每個班級建立一個獨立 GitHub 儲存庫，例如 `class-local-guide`。

1. 在 GitHub 新增儲存庫。
2. 將 `D:\class-sites` 裡的內容上傳到儲存庫最上層。要上傳的是 `index.html`、`class-style.css`、`class-index-report.json` 和整個 `groups` 資料夾，不是外層的 `class-sites` 資料夾。
3. 到儲存庫的 **Settings → Pages**。
4. 在 **Build and deployment** 將來源選成 **Deploy from a branch**。
5. 選擇存放檔案的分支（通常是 `main`）和 `/ (root)`，按 **Save**。
6. 等待 GitHub 顯示公開網址，再用手機與電腦各檢查一次。

GitHub 官方參考：[設定 GitHub Pages 發布來源](https://docs.github.com/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

若學校的 GitHub 組織限制 Pages 功能，請洽管理者開放，或使用學校既有的靜態網站發布流程。

## 七、替換有問題的學生網站

1. 請學生修改內容並重新下載網站 ZIP。
2. 確認要替換的目標資料夾，例如 `groups\02-happy-market`。
3. 先把舊資料夾改名保留，例如 `02-happy-market-old`，並移到 `groups` 外面，避免首頁同時收進新舊兩份。
4. 把新的 ZIP 解壓縮到原本的資料夾名稱。
5. 再執行一次首頁產生指令。
6. 本機預覽確認後，將變更後的 `index.html`、`class-index-report.json` 與該組資料夾重新上傳到 GitHub。

## 八、新增小組或重新產生首頁

把新小組資料夾放進 `groups` 後，重跑同一個指令即可：

```powershell
npm run build:class-index -- "D:\class-sites"
```

這個動作只會重建班級首頁、樣式與檢查紀錄，不會改寫各組網站內容。

## 常見錯誤

- **找不到 `site-info.json`**：通常是只複製了部分檔案，請重新解壓縮完整 ZIP。
- **找不到封面圖片**：`images` 資料夾可能漏傳，請用完整 ZIP 替換。
- **找不到 `index.html`**：可能多包了一層資料夾，請把真正包含 `index.html` 的那一層放到 `groups`。
- **版本不是 1**：請學生用最新版網站產生器重新匯出。
- **首頁沒有某一組**：查看終端機訊息或 `class-index-report.json` 的 `skippedGroups`。

## `site-info.json` 固定格式

老師通常不需要手動修改這個檔案。每個學生網站會自動產生以下欄位：

```json
{
  "schemaVersion": 1,
  "titleZh": "海風步道",
  "titleEn": "Sea Breeze Trail",
  "type": "景點",
  "groupName": "海風觀察隊",
  "coverImage": "images/photo-01.jpg",
  "summary": "沿著海邊散步，觀察潮間帶與港邊風景。"
}
```

`type` 只能是「景點、美食、廟宇、歷史文化、其他」其中之一；`coverImage` 必須是該組資料夾內的相對路徑。
